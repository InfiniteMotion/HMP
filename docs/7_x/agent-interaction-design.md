## 第一章 现实基线——应用骨架与交互语言

**本章命题**

> 交互方案不是在应用上外挂一套聊天 UI，而是把伙伴嫁接进已有的壳、胶囊、对话框与触觉语言。本章先盘清应用的真实骨架——每个设计决策都必须能指认到一处真实代码；随后的章节只在骨架允许的地方生长。

### 1.1 应用壳与导航事实

应用壳为 `AppRoot.kt`（shared-ui commonMain，三端共享）：Navigation3 类型安全路由（`NavDisplay` + `NavBackStack`，fade+scale 转场）、播放态全局动态背景与调色板主题、全局 DialogHost 与 Toast。骨架事实与伙伴的关系：

| 骨架事实 | 代码位置 | 对伙伴的意义 |
|---------|---------|------------|
| NavDisplay 栈式导航，`Routes` 集中定义（Main/Player/Library/Playlist/Settings/AI/Custom/UserData 八模块） | `navigation/Routes.kt` + `NavigationGraph.kt` | 伙伴页面=新增路由，走同一转场与返回栈；`Routes.AI.AI` 已存在（服务商配置页） |
| 主壳为 `HorizontalPager` 四页（Home/Gallery/List/User），`pagerState` 由 AppRoot 持有、与底栏共用 | `MainShell.kt` | 门面替换 Home 第 0 页，pager 仍四页；第 0 页禁用滑出（第二章 2.3） |
| 底栏为 `BottomFusionBar` 双胶囊：左导航胶囊（四 Tab 展开态↔折叠单图标）；右播放胶囊（折叠=旋转封面；展开=封面[点按播放/暂停]+歌名歌手[点按进播放器]+横滑切歌[25% 阈值、渐变提示、触觉]）；播放时自动切播放展开，5 秒无操作回落 | `common/components/BottomFusionBar.kt`（625 行） | 伙伴的常驻邻居与最重要的嫁接宿主；底栏改造为三胶囊（第二章 2.2） |
| Medium 横屏用 `FusionSidebar` 左侧栏替代导航胶囊 | `common/components/FusionSidebar.kt` | 伙伴浮面需适配侧栏形态（第七章） |
| 播放页与歌词页隐藏底栏；播放页下滑关闭，键盘 Space/←/→/L；控制区主行三键（72dp）+副行五键（播放模式/收藏/心动模式/睡眠定时/播放列表） | `player/pages/PlayerScreen.kt`、`player/pages/PlayContent.kt`（`PlaybackControlsButtons`） | 播放页锚点=控制区重排新增「对话」「更多」按钮（第二章 2.5）；键盘 C 键对齐既有先例 |
| 全局对话框宿主：MusicDetail/CreatePlaylist/MusicPicker/PlaylistPicker/Timer 五对话框 + `MessageToast`（纯文字，2s/4s 自动消失） | AppRoot 487-554 行、`dialogs/base/MessageToast.kt` | STRONG_CONFIRM 复用对话框宿主模式；NOTIFY 需要可操作侧条——MessageToast 不够（第四章 4.4 新建） |
| 播放时全局动态背景（专辑封面+调色板），Scaffold 容器透明 | AppRoot 246-263 行 | 对话页天然继承沉浸背景——伙伴坐在你正在听的歌的色彩里 |

### 1.3 交互语言三要素

应用已有一套成熟的视觉与反馈语言，伙伴不得发明第二套：

1. **Haze 毛玻璃材质**——底栏胶囊、Toast、对话框统一为 haze 模糊 + surface 半透明 + 0.5dp 描边（用户可在设置调节强度）。伙伴的一切浮面（轻量浮层、通知侧条、DJ 线）继承同一材质与描边规格。
2. **胶囊形态学**——`RoundedCornerShape(36.dp)` 胶囊是底栏的基本形；动画统一走 `AnimationTokens`（EASE_IN_OUT/TRANSITION）与 spring/tween 组合、`AnimatedContent` 状态切换。伙伴浮面用同一形状族与曲线，不引入新几何。
3. **触觉分级**——TICK（模式切换/阈值越过）、performClick（点按）、LightClick+GestureEnd（手势开始/结束）。伙伴的反馈映射：命令命中并执行=TICK 一次；长按 600ms 唤出轻量浮层=GestureEnd；确认卡逐项跳过=LightClick。

### 1.4 总则

**四条，约束后续全部章节：**

| # | 总则 | 含义 |
|---|------|------|
| 1 | **嫁接优于新建** | 每个伙伴接触点必须指认一个既有宿主（组件/页面/手势/对话框）。全新表面仅当宿主确不存在——全案六个新表面：门面（Home 第 0 页改造）、对话页、轻量浮层、通知侧条、伙伴设置页（AI 页演进）、审计日志页；伙伴胶囊是对 `BottomFusionBar` 的改造而非新表面；其余接触点全部嫁接既有结构 |
| 2 | **一套语言** | 材质、形状、动画、触觉沿用 1.3 三要素，不为伙伴另立体系 |
| 3 | **一锚之外零占位** | 伙伴的常驻足迹收敛为一个胶囊位（底栏第三胶囊）；Tab 不加第五位——门面替换原 Home 第 0 页而非新增；其余浮现物（浮层、侧条、DJ 线）都有原因（任务/消息/确认），用完即隐（第四章展开） |
| 4 | **门面不是功能区** | 门面（第 0 页）是伙伴的脸面：对话与问候的家，不是并列的功能 Tab；工具能力经对话表达，不经门面罗列 |

### 1.5 审计轨迹

| 轮次 | 修订 |
|------|------|
| 1 | 初稿总则 3「底栏不加常驻图标」经锚点讨论否决——伙伴需要恒定可达点，改为「一锚之外零占位」，底栏第三胶囊成为唯一常驻足迹 |
| 2 | 新表面清单由六个收敛为五个：存在感胶囊（被常驻伙伴胶囊取代）、快捷条（被长按浮层取代）、独立对话页（被门面吸收）删除，新增门面 |
| 3 | 播放页锚点从「长按播放键」改为控制区重排（新增对话/更多按钮）——播放键点按已被占用，长按播放键/长按封面均让位于显式按钮 |
| 4 | 轮 2 曾随门面方案删除独立对话页（对话主体并入门面流）；第三章审计否决门面对话流主体后，独立对话页回卷——新表面清单由五个改回六个 |

### 1.6 小结

骨架盘清：一个壳（AppRoot）、两级基座（TabScreen/SubScreen）、一个双胶囊底栏（BottomFusionBar）、一套材质-触觉-动画语言。伙伴的完整交互面=六个新表面+底栏三胶囊改造+播放页控制区重排——第二章给出锚点全景表。

## 第二章 空间与锚点——门面、三胶囊与呼出系统

**本章命题**

> 本章回答「伙伴住在哪、怎么找到它」。伙伴在信息架构中获得一个恒定点：底栏左下的常驻胶囊。点按=回门面（伙伴的家），长按=就地轻量对话。上游「三入口」（agent-design.md 4.4.2）由此收敛为「一主锚点+四辅助」。

### 2.1 决策演进（讨论即审计）

| 轮次 | 方案 | 结论 |
|------|------|------|
| 上游定稿 | 三入口：A 搜索框语义升级 / B 长按播放键 600ms / C MiniPlayer 气泡图标 | B、C 由本章取代；A 保留为辅助入口（第三章 3.4 详设） |
| 讨论 1 | 首页=门面；导航胶囊展开态长按首页图标呼出、折叠态槽位保留伙伴图标；播放页控制区重排 | 长按零视觉线索、可发现性差；但「首页=门面」「子页面空槽」「播放页重排」三个部件存活 |
| 讨论 2 | 门面从 pager 独立为根路由（点按=回家） | 收益=冷启动见伙伴、脱离横滑体系；成本=路由改造+对话流保活问题；被轮 3 取代 |
| 讨论 3（定案） | **三胶囊**：新增常驻伙伴胶囊（点按=切门面，长按=轻量对话浮层）；门面=第 0 页替换 Home，留在 pager | 点按锚点可见可猜可教；pager 内瞬时切换、对话流经 `beyondViewportPageCount = 3` 常驻保活；改动集中于 BottomFusionBar |
| 定案附注 | 锚点层与门面内容层两期交付；第一期接受过渡态（点按=回现有首页）；三胶囊宽度用图标尺寸与间距压缩消化 | 用户确认 |

### 2.2 三胶囊底栏

改造 `BottomFusionBar`：导航胶囊左侧新增**常驻伙伴胶囊**；`bottomTabs` 去掉 Home 项（余三 Tab）。四态形态：

| 状态 | 底栏形态 | 伙伴胶囊行为 |
|------|---------|------------|
| 门面 / Tab 页静止 | [伙伴胶囊] [画廊·列表·我的] [播放圈] | 点按=pager 滚到门面页；长按=浮层 |
| Tab 页播放中 | [伙伴胶囊] [导航折叠·当前Tab图标] [播放展开] | 不变；宽度经压缩消化（2.2.1） |
| 子页面 | [伙伴胶囊] [播放胶囊] | 点按=pop 回 Tabs+滚到门面；长按=浮层。左槽现状为空（`showNavCapsule=false` 时导航胶囊整体隐藏），纯增量零冲突 |
| 播放页/歌词页 | 底栏隐藏 | 锚点由播放页控制区「对话」按钮承担（2.5） |

胶囊规格：36dp 圆角胶囊+haze 材质+0.5dp 描边（总则 2）；内容=伙伴形象（`Avatar` 组件先例；未配置 agent 时=默认形象+首次引导态）；状态徽标=未读/待确认/电台运行时显示圆点。触觉：点按 TICK、长按 600ms 触发=GestureEnd（对齐既有分级）。

集成注意（代码级）：`NavigationExpandedContent` 以 `bottomTabs[selectedTabIndex]` 高亮——去掉 Home 后 pager 页 0（门面）无对应 tab 项，需页↔tab 索引重映射，门面页时三 Tab 均不高亮。

#### 2.2.1 宽度账（Compact 播放态）

按 `PlaybackExpandedContent` 现有尺寸估算 360dp 屏：可用=360−2×16 外边距=328dp；三胶囊（压缩前）=播放展开≈180dp（8×2 内边距+56 封面+12 间距+歌名列下限）+导航折叠≈72dp（8×2+56）+伙伴胶囊≈72dp+2×12dp 间距=348dp，**超约 20dp**。压缩项：导航/控制图标 28→24dp、伙伴形象 56→48dp、胶囊间距 12→8dp、外边距 16→12dp、歌名列宽度上限收窄——合计约省 36-44dp → 富余约 16-24dp。320dp 极窄屏（可用 288dp）：压缩后≈312dp 仍超约 24dp → 极窄+播放态隐藏导航折叠图标（省 72+8dp → 富余），切页靠 pager 滑动兜底。方向已确认，精确规格实施期精算。

### 2.3 门面——第 0 页

两期交付，锚点层先行：

**第一期（锚点层）**：`HomeScreen` 原样不动，点按伙伴胶囊=回现有首页（过渡态，已接受）。

**第二期（门面层）**：Home 改造为门面。门面承载多功能（问候、每日推荐、心动歌单、曲库认识进度、伙伴入口……），**对话不是门面的主体，是门面的一格**——门面提供触发按钮，对话在独立对话页展开：

- **问候区**：伙伴名字+一句问候（人格驱动，健谈度=滑杆）
- **对话触发钮**：门面内一个显眼入口（伙伴形象+「和伙伴聊聊」），点按进**对话页**（第三章 3.2）
- **既有内容归位**：每日推荐、心动歌单保留为门面卡片（伙伴口吻化——推荐附「为什么是这首」）
- **门面留白**：多功能布局由实施期迭代，本档只定「对话=触发钮非主体」这条边界

pager 手术：`userScrollEnabled = currentPage != 0`——门面页禁滑出（对话滚动/键盘/气泡手势不与切页冲突），从画廊向右滑入门面不受阻（顺手的第二路径）。冷启动维持 `savedTabIndex` 恢复——伙伴从第一帧起就在左下角胶囊，不用启动页强刷存在感。`TabPageIndicator` 页点：门面页隐藏（门面不是四分之一，页点属于浏览区）。Medium 横屏 `FusionSidebar`：伙伴项置第一位。

### 2.4 锚点全景（定案）

| 锚点 | 位置 | 手势 | 形态 |
|------|------|------|------|
| **伙伴胶囊**（主锚点） | 底栏左下，一切非播放页状态常驻 | 点按=门面；长按=轻量浮层 | 常驻 |
| 播放页「对话」按钮 | 播放页控制区副行（重排见 2.5） | 点按=轻量浮层（与长按一致——播放页是沉浸态，跳门面打断过重） | 常驻（页内） |
| 搜索框语义升级 | `SearchScreen` | 自然语言输入→结果顶部伙伴条带 | 被动 |
| 键盘 C 键 | Desktop/外接键盘 | C=唤起轻量浮层（Esc 收起，对齐 Space/←/→/L 先例与 3.3 退出规则） | 辅助 |
| 长按浮层（部件） | 底栏上方 | 单行输入条；配置语音端点后浮层内按住说话、松手发送 | 浮现（长按触发） |

主锚点恒定——「找伙伴=看左下角」一条心智。长按浮层的触发与语音分离：长按 600ms=唤出浮层（GestureEnd），按住说话只存在于浮层内，两个长按语义不叠加。

播放页锚点的控制区重排详设见 2.5。

**上游修订注记**：agent-design.md 4.4.2 的入口 B（长按播放键）与入口 C（MiniPlayer 气泡）由本方案取代，文档定稿后在 4.4.2 加注指向本章。

### 2.5 播放页锚点：控制区重排（锚点层一期交付）

`PlaybackControlsButtons`（`PlayContent.kt`）现状：主行三键（上一首/播放暂停/下一首，72dp）+副行五键（播放模式/收藏/心动模式/睡眠定时/播放列表）。重排：

- **主行不动**；**副行重排为五键**：播放模式 · 收藏 · **对话** · 播放列表 · **更多**——心动模式与睡眠定时收入「更多」（心动模式=进歌词页非唯一入口，DotPager 可达；定时激活时倒计时显示为「更多」角标）
- **对话按钮**：点按=轻量浮层（第三章 3.3，与长按胶囊同款）；有未读时按钮角标圆点
- **更多菜单**：底部弹出列表（对齐 `MusicDetailDialog` 弹层语言）：心动模式 / 睡眠定时（定时激活时显示倒计时，`formatTime(remainingTime)` 复用）/ 未来的伙伴动作（加入电台、问这首歌）——**「问这首歌」把当前曲目上下文带进对话页首条消息**
- 三种布局同步：竖屏副行、手机横屏 controls 页、平板横屏左栏——重排逻辑封装在 `PlaybackControlsButtons` 一处，三处调用点自动继承

|----|------|--------|
| 第一期 锚点层 | 三胶囊+长按浮层+播放页重排+C 键；Home 不动 | 完整锚点系统（点按=旧首页过渡态） |
| 第二期 门面层 | Home→门面（问候/对话触发钮/每日推荐与心动歌单口吻化卡片）+独立对话页 | 点按=伙伴的家（多功能），对话经触发钮进独立页 |

解耦理由：锚点层是纯交互骨架，可独立合入验证；门面层内容随 agent 能力（B0-B6）逐步生长，不必一次到位。

### 2.7 审计轨迹

见 2.1 决策演进表——本章方案经四轮讨论定案，演进即审计。后续修订：门面「对话流主体」在第三章审计中被否决（门面多功能定位），2.3 已改为「对话=触发钮」；伙伴胶囊点按语义相应微调——点按=门面（多功能），对话页由门面触发钮进入。另：播放页「问这首歌」入口经审从轻量浮层改为进对话页（浮层承载不了多轮深聊；原第四章审计条目，随 2.5 移入本章）。

### 2.8 小结

空间与锚点章定案：底栏三胶囊（唯一常驻足迹+点按/长按双语义）、门面=第 0 页替换 Home（两期交付）、锚点全景一主四辅、播放页控制区重排（2.5）。上游三入口的 B/C 退役、A 转辅助。

## 第三章 对话——消息模型与三个厚度

**本章命题**

> 本章回答「伙伴怎么说」。对话不是应用里的一个页面，是伙伴的表达方式本身。它有三个厚度：对话页（完整对话的主场）、轻量浮层（不离开当前页的一句话）、搜索框条带（被动触发）。三个厚度共用一套气泡语法与一套消息数据——`agent_message` 是唯一事实，UI 只是读取它的三个姿势。对话页是独立纵深页（SubScreen 级），门面上只有一个触发按钮。

### 3.1 消息模型与渲染分级

`agent_message(id, session_id, role, content, render_hint, created_at)`（上游第六章已定）。交互层补一条渲染契约：**render_hint 驱动 UI 厚度**——

| render_hint | 气泡形态 | 承载 |
|------------|---------|------|
| `text` | 纯文本气泡 | 闲聊、问答、DJ 线、通知语 |
| `song` | 歌曲卡（`AlbumCover`+题名+艺人，点按=SongDetail，菜单=加歌单/分享，对齐 SearchScreen 列表项行为） | 单曲推荐、每日问候的载体 |
| `songlist` | 歌单卡：头部（题名+首数+播放按钮）+`FixedMusicList`（`HeaderConfig.None`+`ItemVariant.Full`+序号，配 `showPinButton=false, showRemoveButton=true` 可增删，复用 HeartbeatSection 同款配置）+尾部动作行（保存歌单/调整/重新选） | 歌单策划结果、电台备选、智能归档预览 |
| `explain` | 折叠卡：紧凑态一句话+「为什么」展开（三轮轨迹：本地初选→云端决策→仲裁修正） | 可解释推荐、跳过重排说明 |
| `confirm` | 确认卡（第四章 4.2 详设） | 批量写确认 |

气泡语法（总则 2）：用户侧=primary 色调右对齐；伙伴侧=surface 半透明+haze、左对齐、顶部小号伙伴名（人格称呼）；语音气泡=文字+左下角小播放键，点按重放音频（音频不落库，重放仅会话内存中；切页后不可重放——诚实呈现，不假装持久）。侧条文案与确认卡（第四章）同守这套语法。

### 3.2 对话页（独立页面，SubScreen 级）

对话页为独立页面（`SubScreen` 基座，标题=伙伴名），从三处进入：门面触发钮 / 浮层回复的「查看」/ 搜索框条带「交给伙伴」。结构自上而下：

```
┌─────────────────────────────┐
│ 问候区：伙伴名+一句话（人格滑杆驱动） │
├─────────────────────────────┤
│                             │
│  对话流（LazyColumn）          │
│  · 伙伴消息（气泡+卡片）        │
│  · 用户消息（右对齐）           │
│  · 任务进行条（工具循环中，       │
│    三点脉动+可取消）           │
│                             │
├─────────────────────────────┤
│ 输入条（常驻底部，胶囊形输入框）    │
│ [输入框] [发送] [🎤按住说话(可选)] │
└─────────────────────────────┘
```

行为细则：

- **滚动**：新消息到达自动滚底（用户正向上回看时暂停自动滚——尊重阅读）；流顶部载入更早消息（分页，`agent_message` 按 session 查询）
- **正在听卡**：问候区下方、流之上嵌一张当前播放小卡（封面+题名+播控），点按进播放页——门面与播放器互达，伙伴坐在你正在听的歌里
- **键盘**：输入条聚焦时对话流自适应（`imePadding`），问候区随键盘收起——聊天场景空间全部让给消息
- **任务进行条**：agent 多步任务（歌单策划）执行中，流内插入进行条（「正在翻你的曲库…」三点脉动+取消）；完成后进行条原地替换为结果卡片——任务的痕迹与结果同位
- **每日问候**：对话页内每日推荐=一条 `song` 卡消息（附 explain 折叠）；门面上每日推荐仍是卡片（伙伴口吻附理由）——同一数据两种呈现，门面管扫视、对话页管深聊

### 3.3 轻量浮层（长按胶囊 / 播放页对话按钮）

底栏上方浮现的单行对话条，不离开当前页：

```
│ (当前页内容)                │
│                            │
│ ┌──────────────────────┐   │
│ │ [🎤] 输入或说话…      [发送] │  ← 胶囊形，haze
│ └──────────────────────┘   │
│ [伙伴胶囊][导航][播放]        │  ← 底栏
```

行为细则：

- **触发**：长按伙伴胶囊 600ms（GestureEnd）或点按播放页「对话」按钮或 C 键；浮现动画=自底上滑入（`AnimationTokens`）——有底栏时贴底栏上方，无底栏页面（播放页/歌词页）贴屏底
- **输入**：单行文本（未配语音端点）；配了端点=文本框+麦克风钮（点按进入按住说话态：按住录音、松手发送、上滑取消——对齐主流语音消息手势）
- **回复呈现**：轻量态回复只有两种——一句话气泡（浮层内直接显示，`text` 类）或卡片摘要（『建好了「深夜」歌单，12 首』+「查看」点按进对话页对应位置）；`songlist` 等重卡片不塞浮层——浮层管轻，对话页管重
- **会话连续**：浮层与对话页同一 `session_id`——浮层里的对话完整进入对话页历史，无二等消息
- **退出**：发送后 2s 无新输入自动收起（或点按浮层外任意处立即收起）；键盘 Escape/收起键同效

### 3.4 搜索框条带（辅助入口 A 详设）

`SearchScreen` 既有 TextField（28dp 圆角）不动，新增判定：输入自然语言（非检索意图）时，结果列表顶部插入**伙伴条带**——

```
┌─────────────────────────────┐
│ 🔍 换点安静的                │
├─────────────────────────────┤
│ ╭─ 🎵 伙伴 ──────────────╮   │
│ │ 我来安排。这句话不是检索，   │   │
│ │ 要交给伙伴处理吗？          │   │
│ │        [交给伙伴] [只是搜索] │   │
│ ╰─────────────────────────╯   │
├─────────────────────────────┤
│ (既有搜索结果列表)            │
└─────────────────────────────┘
```

行为细则：

- **判定**：本地两级漏斗第一级（词表直映射）先行；未命中且输入含意图动词/问句特征时显示条带——检索与对话的分界由漏斗决定，不由 UI 猜
- **「交给伙伴」**：当前输入作为首条消息进入会话，进对话页（浮层与对话页同 session，3.3 已定）
- **「只是搜索」**：收起条带，本次会话内不再对同类输入弹出（记住用户在搜索页的选择——拒绝纪律：不纠缠）
- **空结果页**：`no_results_found` 空态下，下方追加一行「问问伙伴？」轻条带——空结果是天然对话起点（上游 4.4.2 原案保留的精神）

### 3.5 混排与语音细节

- **混排**：语音/文字同会话自由切换（上游 4.4.3 已定）；门面输入条的麦克风钮与浮层麦克风行为一致
- **打断与重连**：会话模式与循环模式共享四层（上游已定），交互层补：实时语音会话中断连，浮层显示「连接中断」态+重连钮；文本消息不受影响（两条通道独立）
- **语音会话入口**：门面输入条麦克风长按进入语音会话模式（全屏语音面板：大波形+字幕浮现+挂断钮）——语音是会话模式不是消息模式，UI 上界清晰

### 3.6 审计轨迹

| 轮次 | 修订 |
|------|------|
| 1 | 初稿浮层回复设计了「悬浮卡片」（卡片直接在浮层上方展开）——自否决：浮层管轻门面管重的分界被自己的设计打破，改为卡片摘要+「查看」跳门面 |
| 2 | 语音气泡「重放」设计经审收敛：音频不落库则切页不可重放，UI 诚实呈现（会话内存内可重放）——不为演示性功能假装持久化 |
| 3 | **门面对话流主体被否决**：门面承载多功能（推荐/心动歌单/认识进度/入口），大量对话内容会挤压功能面——对话降级为门面触发钮，对话主体回到独立对话页（SubScreen 级，第三章 3.2）；第二章 2.3 已同步修订 |

### 3.7 小结

对话章定义三厚度一套语法：`agent_message`+render_hint 分级渲染（text/song/songlist/explain/confirm 五类）；对话页=完整主场（独立 SubScreen 页：问候/正在听卡/任务进行条/每日消息化），门面只放触发钮不放对话主体；轻量浮层=一句话通道（同 session 连续、回复二分法）；搜索框条带=被动入口（漏斗判定+拒绝纪律）。上游 5.4 形态学的全部承诺（气泡双形态/富回复/Progressive disclosure）在此落地为具体组件。

## 第四章 行动——许可、确认、通知与留痕

**本章命题**

> 空间与对话回答了「在哪、怎么说」；本章回答「怎么做才安全」。上游 5.2/5.3 的许可阶梯与质量纪律在此落为具体 UI：确认卡片流（CONFIRM）、通知侧条（NOTIFY）、强确认对话框（STRONG_CONFIRM）、DJ 线与存在感的呈现形态。判据只有一条：**用户不怕伙伴犯错，就怕错了回不去——撤销永远在场**。

### 4.1 通知侧条（NOTIFY，新建组件）

既有 `MessageToast`（纯文字 2s/4s 自动消失）不可操作，不满足撤销需求。新建 `AgentNoticeBar`：底栏上方侧条（无底栏页面贴屏底，与轻量浮层同锚规则），haze 材质胶囊，左侧伙伴形象小图标——

```
│ (页面内容)                   │
│ ╭─────────────────────────╮ │
│ │(小知) 建好了「深夜」歌单，12 首  ↩撤销│ │  ← 4s 自动退场
│ ╰─────────────────────────╯ │
│ [伙伴胶囊][导航][播放]         │
```

- **触发**：NOTIFY 级工具执行完成（建歌单/加歌单/重排队列可见类）；同一时刻最多一条，新侧条顶替旧侧条
- **撤销**：`↩撤销` 点按=回滚该动作（触觉 Confirm）；4s 自动消失后撤销入口转移至审计日志页（4.4）——**撤销窗口过期≠不可逆**，只是入口变深
- **与 Toast 的分工**：系统消息（保存成功/失败）仍走 `MessageToast`；伙伴动作通知走侧条——两个通道不混用

### 4.2 确认卡片流（CONFIRM）

批量写（歌单策划多首、批量归档）在对话页流内以 `confirm` 卡逐项呈现（render_hint 第五类，第三章 3.1）：

```
│ ╭─ 小知想这么做 ─────────────╮ │
│ │ 建歌单「深夜」，包含 12 首：    │ │
│ │ 01 夜空中最亮的星  [✓选中]     │ │
│ │ 02 晚风  [✓选中]             │ │
│ │ …（逐项勾选跳过）              │ │
│ │      [跳过全部] [照做]        │ │
╰─────────────────────────────╯ │
```

- **非模态**：卡片在流内，不挡输入条——用户可以继续打字改要求（「把 05 换成慢一点的」）
- **逐项可跳过**：取消勾选即跳过该项；「照做」只执行选中项；「跳过全部」=本卡作废（拒绝纪律：不纠缠，伙伴可换方案不可重提）
- **执行后**：选中项执行→NOTIFY 侧条（4.1）+卡片状态更新为「已建 9 首，跳过 3 首」
- **语音会话中**：CONFIRM 降级为口头确认（上游 5.2 已定）——语音面板内伙伴念出关键项（「12 首，头三首是…」），用户答「好/改/不要」

### 4.3 强确认（STRONG_CONFIRM）

删歌单、改 ID3 文件：传统模态对话框（复用 AppRoot DialogHost 宿主模式），明示不可逆后果；红字按钮；无撤销。`EditMusicTagsScreen` 已有系统级写权限确认（MediaStore 授权框）在前，伙伴侧确认叠加在其后——双确认链（伙伴问意图→系统问权限），顺序不合并。

### 4.4 审计日志页（新建页面，SubScreen 级）

伙伴的一切自主动作留痕。入口：伙伴设置「记忆与信任」分区。`agent_audit_log` 表驱动，按时间倒序：

```
│ 21:42 重排播放队列   为什么 ›   ↩撤销 │
│ 21:37 建歌单「深夜」  为什么 ›  已撤销 │
│ 21:30 推荐夜空中最亮的星  为什么 ›     │
```

每行：动作+「为什么」展开（一句紧凑理由→T0 行为证据，上游 5.4：「你 23:00 后跳过了两首快歌…」）+可撤销动作的撤销钮。**撤销边界**：撤销仅对未被用户后续修改的动作有效——歌单建好后被用户增删过歌，撤销钮降级为「删除」（走 STRONG_CONFIRM）；重排队列类撤销始终可用（覆盖即可逆）。过期动作显示结果状态。**信任来自随时可查，不是每次都说**。

### 4.5 存在感呈现（PresenceBus 的 UI 面）

| 呈现 | 形态 | 触发 |
|------|------|------|
| 通知侧条 | 4.1 | NOTIFY 完成 |
| DJ 线 | 对话页流内 `text` 消息+门面问候区轮换句 | 曲间衔接（预生成零延迟，上游场景 4） |
| 正在听卡 | 对话页顶部 | 常驻 |
| 胶囊徽标 | 伙伴胶囊圆点 | 未读/待确认/电台运行 |

DJ 线在门面的呈现：问候区一句话轮换（不弹窗不打扰）——健谈人格多轮换、寡言人格只在显著事件时换句；对话页内 DJ 线沉淀为流内消息（可回看）。**播放中不弹任何伙伴浮面**（上游 5.3 硬纪律：用户手势进行中永远闭嘴）。

### 4.6 审计轨迹

| 轮次 | 修订 |
|------|------|
| 1 | 初稿侧条撤销窗口 4s 后失效——自否决：可逆性是原则不是限时优惠，撤销入口转移至审计页而非消失 |
| 2 | DJ 线初稿为「曲间顶部横幅」——改为门面问候区轮换+对话页沉淀：横幅违反「播放中不弹浮面」硬纪律 |
| 3 | 自查修订：审计页撤销补边界——迟到的撤销可能变成破坏性删除（用户改过的歌单一键撤销=删歌单），被修改过的动作撤销降级为删除（走 STRONG_CONFIRM） |

### 4.7 小结

许可与呈现章落地四件 UI：`AgentNoticeBar` 通知侧条（4s 退场+撤销入口转审计页）、`confirm` 确认卡片流（非模态+逐项跳过+语音口头化）、STRONG_CONFIRM 双确认链（伙伴问意图→系统问权限）、审计日志页（为什么+撤销）。存在感四形态全部服从「不打断播放中手势」硬纪律。

## 第五章 既有页面的伙伴化改造

**本章命题**

> 表达与行动回答了「怎么说、怎么做」；本章回答「既有页面长出什么」。伙伴化不新增功能页堆叠，而是让既有页面长出伙伴的器官：User 页长出伙伴卡，AI 页演进出人格与语音，歌单页长出解释性，歌词与艺人页长出深读入口。改造以「既有结构+新槽位」为纪律，不重排页面骨架。

### 5.1 User 页：伙伴卡

`UserScreen` 的 `SettingsListCard` 上方插入**伙伴卡**（对齐 `profileCard` 视觉规格：透明底+outlineVariant 0.5dp 描边）：

```
╭─────────────────────────────╮
│ (伙伴形象)  小知           › │
│            健谈 · 已认识 2312/2500 │
╰─────────────────────────────╯
```

- 左=伙伴形象（`Avatar`），中=名字+两行摘要（人格名+曲库认识进度——「阅历」的产品化呈现，上游 2.2.2），右=chevron；点按进伙伴设置页（5.2）
- agent 未配置时：伙伴卡变为「认识你的音乐伙伴」引导卡（默认形象+一句介绍+「去配置」→ AI 页）——配置入口前移，不隐藏能力

### 5.2 AI 页 → 伙伴设置页（演进不推翻）

## 第六章 场景交互流——十五个场景逐一落地

**本章命题**

> 上游 4.3 的十五个场景每个给出端到端交互流：入口→过程→许可→呈现→反馈闭环。这是对前五章组件的一次总装配——每个场景只允许使用已定义的表面（胶囊/浮层/对话页/侧条/确认卡/审计页），不新增交互件。

### 6.1 陪伴态（听音乐时）

| # | 场景 | 交互流 |
|---|------|--------|
| 1 | AI 电台 | 电台开启=对话页 `songlist` 卡（「今夜电台 · 12 首备选」+播放）；播完续歌静默执行（SILENT）；胶囊徽标=电台运行点；每次续选的「为什么」入审计页 |
| 2 | 跳过感知重排 | 连跳两首→重排（SILENT）+侧条一句话（「换了一批安静的，↩恢复」）——重排可逆故侧条带撤销 |
| 3 | 一句话切换 | 浮层输入「换点安静的」→漏斗判定→执行+侧条；对话页同步沉淀 |
| 4 | DJ 衔接 | 曲间门面问候区轮换句+对话页 `text` 沉淀（第四章 4.5）；预生成零延迟 |
| 5 | 智能睡眠定时 | 对话页/浮层说「半小时后停」→**直接执行+侧条**（「半小时后停 ↩取消」）——用户刚明说的可逆动作无需再确认（过度确认违反许可无感）；「更多」菜单手动定时（TimerDialog）不变 |

### 6.2 工具态（管理曲库时）

| # | 场景 | 交互流 |
|---|------|--------|
| 6 | 曲库问答 | 浮层或对话页问答（「这个月听了多久」）→`text` 回复；数字类答案配一句来源（「按播放记录统计」） |
| 7 | 歌单策划 | 对话页多轮：需求澄清（伙伴反问 1-2 轮）→任务进行条（「正在翻你的曲库…」）→`confirm` 确认卡逐项勾选→执行→NOTIFY 侧条+歌单卡（尾部动作行：保存/调整/重选） |
| 8 | 曲库医生 | 触发=门面卡片「体检报告有了」（月度）或对话页主动问；报告=对话页 `explain` 卡（标签缺失的高频歌 5 首+30 天未播新歌+过气心头好）+逐项动作（补认识/加入歌单） |
| 9 | 标签修正 | 歌曲详情/对话中说「这首不是爵士」→轻量确认（侧条式「已改为摇滚，来源：你 ↩撤销」）→T1 写入+置信度记录 |
| 10 | 智能归档 | 新歌导入→后台归类（NOTIFY 侧条「3 首新歌归到『最近添加』」）→歌单页解释行（5.3） |

### 6.3 惊喜态（回顾与发现）

| # | 场景 | 交互流 |
|---|------|--------|
| 11 | 听歌报告 | 月度：门面卡片入口→报告页（图表复用 `ListeningChart` 语言）+伙伴叙事段（「我们的这个月」） |
| 12 | 遗忘唤醒 | 胶囊徽标（低频）+对话页消息（「你 90 天没听这首曾经的最爱」+`song` 卡）；点开才算送达，不点开不追问 |
| 13 | 可解释推荐 | 每日推荐=门面卡片+对话页 `song` 消息（explain 折叠：「为什么是这首」→T0 证据） |

### 6.4 学习态（内容深读）

| # | 场景 | 交互流 |
|---|------|--------|
| 14 | 艺术家/专辑深读 | 播放页「更多」→问这首歌；或 Artist/Album 页入口→对话页串联卡片（曲库内全部曲目 `songlist`+播放统计+富化正文） |
| 15 | 歌词翻译注解 | 歌词页「问歌词」钮（5.4）→对话页：翻译卡（对照排版）+典故 `explain` 卡 |

### 6.5 反馈闭环核对

十五场景逐一核对闭环成立（上游第二章判定标准）：

- 电台/跳过感知/一句话切换：听下去或跳过→改变下次决策（T0 回写）✓
- 歌单策划/智能归档：保存或跳过→同类建议的信任阶梯演化 ✓
- 标签修正：修正即 T1 写入 ✓；遗忘唤醒：点开/忽略→唤醒策略调整 ✓
- 每日推荐：次日推荐根据前日行为调整 ✓；DJ 线：说完即沉淀，行为回写同电台 ✓

### 6.6 审计轨迹

| 轮次 | 修订 |
|------|------|
| 1 | 场景 12 遗忘唤醒初稿用「通知侧条」推送——改为胶囊徽标+对话页消息：侧条是动作反馈通道不是主动搭话通道，主动搭话只经低频徽标与门面 |
| 2 | 场景 9 标签修正初稿弹确认卡——降为侧条式轻确认：单标签改写可逆且高频，确认卡过重 |
| 3 | 自查修订：场景 5 睡眠定时初稿用确认卡——降为直接执行+可取消侧条：用户刚明说的可逆动作再确认即过度确认 |

### 6.7 小结

十五场景全部装配于已有表面：陪伴态走浮层/侧条轻通道，工具态走对话页确认卡重通道，惊喜态走门面卡片/徽标，学习态走深读入口。无新增交互件；每个场景闭环成立。
